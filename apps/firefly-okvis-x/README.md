## Rust 独立行为测试

六个包新增 **51 项** Rust 原生测试，运行时不读取 C++、参考输出、词典或图像资产。
采用解析场景、独立数学公式、中心差分、几何不变性和属性生成相结合的方式，
测试真实检测、匹配、检索、RANSAC、图优化及深度积分；错误路径检查返回值及状态保持。
容差按浮点精度、差分步长与求解停止条件明确写在测试源码中。

| BRISK / AGAST | 6 | 384 位独立汉明定义、矩形像素直接求和、512 种角点环、描述子平移及匹配边界 |

| OpenGV | 5 | 已知三维场景的三角化/EPnP、20% 离群点的真实 RANSAC、退化与错误输入 |

其中 13 项使用 proptest，默认每项 256 组输入，失败会缩减并将种子保存在测试旁的
`.proptest-regressions` 文件，后续自动重放；该文件应随对应修复提交。
扩展运行使用 `PROPTEST_CASES=2048 PROPTEST_RNG_SEED=20261021`，
共验证 26,624 组新生成的属性输入，另重放既有种子。
现有 CI 的 `cargo test --all-targets` 自动发现这些用例，无需新增专属测试入口。
使用 cargo-mutants 在临时副本中抽查 7 个变异：汉明 XOR、词袋评分、
流形加法、投影主点符号及占用支持边界，**7 个均被测试捕获**，无超时或不可编译变异。
这只是上述变异的敏感性抽查，不是全源码变异覆盖率。
设计参考 nalgebra 的几何测试、
矩阵分解重构测试以及
proptest 的缩减与失败重放。

这些用例保留已确认的兼容边界：例如 SE08 的高位 Morton 解码拒绝有专门用例，
不会因编码支持 19 位就声称所有 19 位三维键均能解码。闭环用例验证相对位姿图优化，
不代表完成真实图像回环识别、完整滑窗边缘化、异步调度或数据集轨迹质量验证。

独立数学测试验证算法契约；保留的地图夹具锁定 f32 数值行为。夹具回归与独立公式、
中心差分和解析场景互相补充，不以 Rust 重新生成基线作为算法正确性的证明。

## 与 C++ 的差异及处理思路

对照上游版本为
`38043e4afe56d9b32a98434cc74e723737dd2bce`。
迁移期间 C++ 快照未改；上游版本见上文。除下列明确行为选择与库兼容差异外，
Rust 以原版公式、阈值和分支为准。
编译错误、接口漏译和已经对齐的译文错误不作为永久差异记录。

### 源码行为与翻译选择

| 编号 | C++ 源头行为 | Rust 处理思路 |
|---|---|---|
| S01 | `PoseError` 的对角信息矩阵构造路径不赋值协方差，默认构造也不提供有效权重 | 用 `Option` 表达未赋值字段，保留访问接口，不自行补算协方差。通用矩阵构造遇奇异信息时协方差也为 `None`，不返回伪造逆矩阵；残差权重保留 Eigen 未检查 LLT 状态时的部分分解结果，不换成对角平方根或加 epsilon。 |
| S02 | 三个畸变模型用 `parameters.cols()` 检查参数数量，合法列向量被拒绝 | 用 `.len()` 检查元素数量，对应 C++ 的 `.size()`；保留错误长度返回 `false`。 |
| S03 | 普通 `DepthError` 保留 `p_z = 0`，只有单边版本计算实际深度，但普通版本仍提供深度雅可比 | 按既定决定保留公式和分支。普通版本的残差/雅可比疑点不擅自修正；单边版本保留原来的深度下界约束。 |
| S04 | `FBrisk::toMat32F()` 的 `j` 按位偏移递增，却读取 `desc[j]`，对 48 字节描述子越界 | 读取 `descriptor[j / 8]`，展开到对应的八列；每位仍输出 `0` 或 `1 << bit`，不另外归一化成 `0/1`。 |
| S05 | 针孔相机用 `intrinsics.cols()` 检查至少四个内参，合法列向量被拒绝 | 用 `.len()` 检查 `4 + 畸变参数数目`，通过后继续更新参数。 |
| S06 | 针孔齐次投影在 `w < 0` 时对输入取负，却未对点雅可比施加链式法则的负号 | 普通和外部参数两个入口都对前三列点雅可比乘以输入符号；第四列保持零，内参雅可比不额外变号。 |
| S07 | 针孔反投影把像素归一化缩放左乘去畸变雅可比，两个焦距不同时交叉项错误 | 输出前两行为 `J_undistort * diag(1/fu, 1/fv)`，第三行为零。 |
| S08 | EUCM 带雅可比反投影遗漏有效域门限的倒数，与普通版本判断不同 | 两个入口共享普通版本的门限 `1 / (beta * (2 * alpha - 1))`；保持严格大于比较及 `alpha > 0.5` 的分支条件。 |
| S09 | EUCM 反投影雅可比明确未实现 | 保持原样：有效域内置零、记录错误日志并返回成功；有效域外返回失败，不补写雅可比。不把该能力视为已实现。 |
| S10 | ViGraph 的 GPS 反向查找先解引用、后判断是否到 `rend()`；IMU、异步 GPS 和 LiDAR 补偿的积分循环先读 `(it + 1)`，再判断是否到末尾；`ImuError::append()` 还将输入队列的迭代器与成员队列的 `end()` 比较 | Rust 反向查找用有界状态查询；早于全部状态的测量不解引用末端。积分只遍历有效相邻样本，检查时间覆盖，使用索引代替跨容器迭代器。正常积分公式不变；空数据、覆盖不足等路径显式返回错误或原接口的失败状态，不复刻未定义内存访问。 |
| S11 | 体素地图用 range-for 遍历哈希表时删除当前元素，使循环迭代器失效 | 用 `HashMap::retain` 安全删除；仍以体素首点和严格距离 `>` 判断整块删除。浮点体素索引仍向零截断；非有限或超出 `i32` 范围的坐标显式拒绝。 |
| S12 | 相对位姿适配器计算第二帧的不确定度时，`fu2` 取自第一帧的第二个相机 | 原样保留。两帧相机内参相同时无差别；内参不同时使用哪一帧的焦距，待确认。 |
| S13 | 同一适配器中，第二帧反投影失败时给第一帧的 bearing 写入回退方向，第二帧继续归一化 | 原样保留写入目标，不擅自改成跳过匹配或给第二帧回退。缺少有效数值时不读取未初始化内存。待决定是否修正为第二帧回退。 |
| S14 | `NCameraSystem::computeOverlaps()` 重算时仅设置 `true`；`resize()` 保留旧值，因此重算后没有重叠的相机对仍可能标为有重叠 | 原样保留。待决定是否在每次重算前清空布尔重叠表。像素重叠图仍每次重新计算。 |
| S15 | `Frame` 拷贝构造只复制图像、几何、后端和分类标志，不复制关键点、描述子、路标、反投影或分类矩阵 | Rust `Clone` 保留该拷贝语义，包括可能出现“已分类但没有分类矩阵”的状态。是否改成完整帧拷贝属于语义决策，不能仅凭成员遗漏判定作者意图。 |
| S16 | 快照声明了 `LidarMotionCompensation` 构造函数、`PseudoImuError::propagation()` 和异步 GPS 默认构造函数，但全仓没有对应定义 | 不猜测实现。前两项用明确的能力 trait 表达，没有默认实现；异步 GPS 只提供有效的有参构造。LiDAR deskew 实际使用有定义的 `BatchedLidarPropagator` 初始化及相同积分公式，译在 `submapping_utils.rs` 内。 |
| S17 | `SubMapConfig(file)` 没有委托默认构造；缺少配置节点或前几个键时，字符串为空，三个标量字段可能未初始化 | 当前 Rust 配置使用 TOML 和 `serde(default)`，缺键使用默认构造的完整默认值，解析错误仍返回错误。这是明确的安全配置选择；是否改成要求这些键必填，待决定。 |
| S18 | IMU 预积分与静态传播使用不同的偏置雅可比和饱和噪声公式；协方差传播的 `F(0,12)` 保留正的二次项 | 各入口逐式保留：预积分使用 `C1 * Jr * dt`，静态传播使用 `dt * C1`，各自保留原饱和乘数及协方差符号。不因看起来不一致而统一公式；公式正确性尚未作独立推导裁决。 |
| S19 | 双位姿图因子登记观测时，`poseIdx` 默认为 0，仅第二个位姿第一次登记时赋 1；动态外参的索引使用 `6 + offset + ci * 6`，其中 `offset = poseIdx * numCams` | 两处均保留源码索引。实时因子按元数据索引，常量因子按原来的 `6 + 6 * i` 分块；缺少外参或实际越界显式报错。是否调整 poseIdx 和 offset 的单位，待决定。 |
| S20 | 图因子只请求 minimal Jacobian 时仍可能解引用空的 ambient Jacobian 数组；仅请求参考位姿、不请求另一位姿时，参考位姿雅可比保留零 | 空数组路径显式返回失败，不制造矩阵；依赖请求组合的零雅可比分支原样保留。待决定是否让两种输出请求完全独立。 |
| S21 | 图因子新增观测或转回重投影因子时不重置 `isComputed`；`compute` 清空路标 ID 索引，之后 `getLandmarks` 不再返回原路标 | 原样保留缓存标志、索引清理和转换后的矩阵清零行为，不自行引入重算或补存路标。 |
| S22 | Component 的 FRAME 关键点组或 EDGE_IMU 测量组恰好在 EOF 结束时，不执行遇到下一标签时的收尾；EDGE_OBS 读入测量及信息矩阵后没有使用它们 | 保留分组结束条件及观测重建路径。是否在 EOF 收尾、是否使用文件中的观测权重，待决定。输出保留 17 位有效数字及可互读标签；科学记数法与 C++ defaultfloat 文本不逐字节相同。 |
| S23 | Component 保存首个状态时若存在 previous IMU link，会对状态容器的 `begin()` 执行递减；读取固定 48 字节 BRISK2 时也没有完整的输入长度保护 | 对首状态前驱不存在、短描述子、缺字段及非法时间显式报错，不访问不存在的状态或内存。正常记录顺序及描述子格式不变。 |
| S24 | 深度配准的临时点云按输出尺寸分配，却按输入尺寸写入；输出任一维小于输入就可能越界 | 保留输出尺寸的临时平面及其空白点处理；输入超出该平面时显式拒绝，不擅自改成另一种配准算法或分配尺寸。 |
| S25 | Trajectory 先以 `current.omega_S - current.b_g` 存相对状态，恢复时再次减关键帧 bias；更新状态不自动清空已有传播缓存 | 原样保留双减和缓存生命周期，保留显式 `clear_cache`。常速模型的前向/后向外推起点与比例也照原分支，不按模型名称重写。 |
| S26 | DatasetReader 的异步 depth 最小时间候选被注释禁用；非同步组中带 depth 的路径会再次读取并推进普通相机帧；同步循环的 `needSync` 不在每轮重置 | 保留普通相机驱动、双重推进及同步分支；真实越界显式报错。是否修复异步 depth 和同步状态重置，待决定。 |
| S27 | DatasetReader、RPG/X/Leica Reader 空 IMU/GPS/LiDAR 输入的一些错误路径返回 `-1`，但函数返回类型为 bool；Leica 路径按 `path + "gnss.csv"` 拼接；`stopStreaming` 只 join，不先请求取消 | 空输入返回错误，避免报告成功；路径拼接和等待读完的停止语义原样保留。调用方仍须提供原路径约定，不把 join 当作立即取消。 |

### 图像重采样的库兼容差异

当前图像去畸变调用 PureCV 的公开接口，通过 `DynamicMatrix` 分派到具体像素类型。
校正图保留 C++ 的整数坐标和每轴 5 位小数，采样位置精度为 `1/32` 像素。

当前锁定的 PureCV 版本 `e07b882e792a3c7221178d5163d9ed2eaba92a92`
对 `u16/i16` 采用标量线性重采样，其中
`T::from_f32(val)`
会截断小数，与 OpenCV 的整数输出取整不同。例如输入 `[0,3;0,3]`，采样位置
`x = 0.5, y = 0`，PureCV 输出 1，OpenCV 4.10 输出 2。
这是 PureCV 的 OpenCV 兼容问题，不是原 OKVIS2-X 投影算法的问题。

**该差异尚未消除。** 处理方向是在 PureCV 层对齐各支持像素类型的取整与饱和转换语义，
完成与 OpenCV 的逐像素对照后更新依赖。不能仅因更换了图像库就认定结果完全一致。

### CNN 输入缩放的库兼容差异

同一 PureCV 版本的
`resize`
使用浮点双线性插值后 `round()`，与 OpenCV 4.10 的 `INTER_LINEAR` 整数实现不逐像素一致。
例如 `u8` 灰度输入一行 `[17,70]`，缩放到宽 3、高 2，OpenCV 输出
`[17,43,70;17,43,70]`，PureCV 输出 `[17,44,70;17,44,70]`。

这不是前节 `remap` 的截断问题。Frame.cpp
在分类前调用 `resize`，所以该差异会进入归一化后的网络输入。
Rust 当前保留 PureCV 调用，**该差异尚未消除**；处理方向是在 PureCV 层对齐 OpenCV
对应类型的插值与转换，再更新依赖。未用修改网络均值、方差或分类阈值抵消像素差异。

### 彩色图像转灰度的库兼容差异

离线图像适配器用 `image` 解码 PNG/JPEG，保留 `Unchanged` 模式的 u16 深度及 BGR/BGRA
布局；PNG 灰度加透明通道按 OpenCV 展开为 BGRA（u8/u16 均覆盖）；彩色输入转灰度复用 PureCV。锁定版本的 SIMD 内核使用
`(77*R + 150*G + 29*B + 128) >> 8`。
同一个 RGB 三原色 PNG，Rust 输出 `[77,149,29]`；本地 OpenCV 4.10 的
`imread(IMREAD_GRAYSCALE)` 输出 `[76,149,29]`，`cvtColor` 输出 `[76,150,29]`。

这是数值兼容差异，**尚未消除**。当前保留 PureCV 调用，不调阈值抵消差值；处理方向是
在图像后端分别对齐解码灰度模式与颜色转换的舍入语义，再验证依赖更新。
原生 u8 单通道输入直接保留像素，不经过该彩色转灰度步骤；JPEG 及更多颜色输入尚未逐像素对照。

### 深度存储 exp/log 的数值库兼容差异

`ViInterface` 的深度存储变换使用 OpenCV `cv::exp` / `cv::log` 和 MatExpr 缩放。
Rust 保留缩放精度及顺序，使用标准库指数、对数；对 `log` 的符号忽略、零、次正规数、
NaN、无穷及 f64 `exp(NaN)` 明确映射当前 OpenCV 4.10 的特殊值语义。
例如 f32 深度解码的 `log` 变换对零输出 `1270`，不是标准数学 `ln(0)` 的无穷。

**正常有限值仍不逐位一致。** OpenCV HAL 使用近似算法，标准库采用另一实现。
f32 的部分结果差 1 ULP；f64 编码输入 `1` 时，C++ 输出 `0.93303299153673291`，
Rust 输出 `0.9330329915368074`，差约 `7.45e-14`。这是深度存储编解码路径的数值库差异，
尚未通过替换底层实现消除，不通过修改深度比例、阈值或融合公式抵消。

### OpenGV 数值库兼容差异

位姿算法保留原来的求逆、法方程、消元顺序及停止条件；Eigen 与 Rust 数值库的求和、
LU/SVD/QR 等实现不保证逐位相同。`RustNumericalBackend` 使用 faer 0.24.4 提供完整
矩形 SVD 和复数特征对；`minpack_lm.rs` 逐式实现 Eigen 旧版 LM、lmpar2、qrsolv 和
NumericalDiff 前向差分，QR 使用 nalgebra。正式源码没有 C++ 子进程或 FFI 数值宿主。

LM 的 `maxfev` 统计包括完整 Jacobian 差分及 trial，保持原版在完整 trial 后判断预算；
不能用成熟 LM 库的 callback 硬截预算替代。Rosenbrock 的预算 1/5/10/1000 对照中，
两端函数调用数同为 5/5/10/70；预算 10 时终值最大差约 `6.66e-16`。
**其他用例仍未数值/终止对齐：** 强列 pivot 的三变量系统预算 20/1000 时，终值最大
`abs(Rust-C++)/(1+abs(C++))` 约 `2.48e-6` / `3.10e-8`；Powell 奇异函数预算 1000 时，
Eigen 用 360 次评估收敛至约 `1e-14`，Rust 用 1004 次评估触及预算、终值约 `4.83e-11`。
QR 主元选择存在确定差异：Eigen 按列范数选列，nalgebra 按剩余块最大绝对元素选列。
该差异会改变迭代轨迹；尚未隔离其对全部终值差异的贡献，不将这些用例计为一致性通过。

**部分求解结果尚未数值对齐。** 现有三组对照中，按
`abs(Rust - C++) / (1 + abs(C++))` 计算，Nister 最大约 `2.46e-7`，
GE 约 `4.66e-4`，relative 非线性约 `2.46e-5`，point-cloud 非线性约 `1.44e-7`。
GE 还保留随机扰动重试，其 Rust 与 C++ 随机序列不保证一致；没有把这些结果计为一致性通过，
也没有仅凭量级将全部差异归因于库舍入。

六点法的合法几何输入中，法方程条件数最高约 `2.24e10`，消元矩阵约 `5.08e14`，
微小的矩阵计算差别会放大为明显的候选集差别。三组最接近真值的候选仍对应相同索引，
但首组旋转到真值的 Frobenius 距离，C++ 约 `0.00769`、Rust 约 `0.0180`。
当前保留原算法，没有改成更稳定的替代分解、增加 epsilon 或放宽门槛；
进一步对齐数值原语还是调整原算法，属于待决定的兼容范围。

特征向量还存在整体正负号不唯一的问题：一个直接比较差值约 `1.75` 的用例，
旋转、平移实际差值分别只有约 `4.22e-12`、`2.08e-12`；不将特征向量符号差直接当成位姿错误。

### Rust 表示与依赖能力边界

- 无有效默认值的测量、参数和估计必须显式构造；未赋值的向量、权重、标志使用
  `Option`，不制造有效的传感器零读数。原未赋值权重的读取显式失败。相机外部参数长度不足或缺少必需的雅可比输出时
  返回失败；奇异信息矩阵保留 Eigen 部分 LLT 权重，协方差为 `None`，不因转换失败而 panic。
- 图像、特征点、矩阵、时间和容器复用 PureCV、nalgebra、jiff 与标准库；
  manifold 使用能力 trait，图像和相机句柄使用 `Arc`，具体相机访问使用标准 `Any` 下转型。
- BRISK/AGAST 的检测、尺度空间、细化、描述子（含相机感知）、匹配、降采样、滤波、
  Harris 评分及均匀化已有本地 Rust 实现；Frame 与前端工厂通过具体 BRISK 适配器调用。
  Supereight2 的针孔深度占用建图、预处理、自动网格缓存及配置已有独立 Rust 译文，
  `OccupancyMapBackend` / `OccupancyMappingRuntime` 连接积分、场查询和图对齐约束；
  相关行为和验证边界见本文地图审计记录。
  网络推理继续由精确能力 trait 注入。OpenGV 的适配器、绝对/相对
  位姿公式、多项式消元及 SAC 已有本地算法，Frame SAC 的具体 OpenGV 适配器和
  回环位姿精化也有实现；数值后端与原版的兼容边界见上节。
- BRISK 数值对照覆盖当前 x86 路径，ARM/NEON 没有在目标硬件运行；原本未实现的
  16 位 ARM 降采样返回错误，不宣称具有完整跨平台等价性。
- Ceres 数值雅可比检查的 problem/manifold 查询、Component 对 ViGraphEstimator 的注册、图像编码、立体校正、
  OpenCV LUT/字体/AA/三次插值绘制同样保留明确的后端能力边界；文件自身的序列化、
  Schur 消元、深度融合、NMS、对象关联、投影及回调路由已有实际 Rust 逻辑。
- VI 和子地图配置输入改用 TOML，保留原配置键及默认参数；不直接兼容原 YAML 文件。
  随机采样使用 Rust 随机库，保持采样规则与所需输出顺序，不承诺与 C++ 随机序列一致。
- 不确定度采样保留稳定升序和实际选取索引；不把“点数与 sigma 数不等”一概判为失败。
  实际越界显式失败；NaN 会破坏原比较器的严格弱序，Rust 显式拒绝。
- `MstGraph.hpp` 注释称最大生成树，但源码升序排序实际求最小生成森林；Rust 保留实际
  排序、合并和输出追加行为，文档按最小生成森林描述，不改成最大树算法。

### 线程调度与文件格式边界

- `ThreadedSlam` 使用独立 processing owner 线程持有图和前端，传感器通过独立队列端点输入；
  publishing、visualisation、CNN 和全图优化各有实际线程。全图求解传递数值快照，结果由
  owner 提交并处理 backlog，不给 `Rc<RefCell<_>>` 添加不安全的 `Send/Sync`。
- 逐相机检测和匹配分块目前串行执行；保留原分块统计、候选顺序和严格比较，但未保留
  C++ 跨相机/匹配线程并发及当前帧检测与前次实时优化重叠。`stop_threading` 等待任务后
  保留 graph owner 处理最终 BA/保存/导出，最终 shutdown 才 join owner。
  **这是待确认的调度取舍，不能据此宣称性能或调度与 C++ 相同。**
- `RustGraphSolver` 实现实际因子评估、固定块与 manifold、三种 robust loss、传统 Dogleg、
  Ceres LM、稀疏正规方程 Cholesky、稠密 Schur 消元与回代、增广稠密 QR、停止条件及时间回调；分解使用 faer 和 nalgebra。
  全图任务仅携带独立数值/因子快照，同一底层地图只冻结一次，完成后回传 IMU/GPS 缓存。
  因子和块装配目前串行，`num_threads` 不表示已恢复原 Ceres 并发，性能与时限内迭代数
  不承诺相同。16 组原 Ceres 对照的已完成迭代数一致，参数最大归一化差约 `1.27e-17`；
  巨大固定代价的汇总仍存在浮点归约差，不声称逐位相同。
- GeographicLib 本地坐标转换、网络推理、立体校正和部分绘制原语仍由可选能力接口注入。
  两个 App 的流程源码均纳入正式 Cargo 模块树；默认二进制装配同步离线入口、BRISK、
  OpenGV、图优化和 Supereight2 针孔占用建图，PNG/JPEG 图像读写由 `image` 提供，灰度转换复用 PureCV。
  TIFF 深度存储后端尚未提供，默认工厂遇到该格式返回错误。
  原生 UI、双目校正、CNN/神经网络与硬件 SDK 没有由默认工厂提供实现；相关配置显式失败。
  相机和畸变接口要求 `Send + Sync`，由编译器检查模型和共享只读标定的跨线程使用，
  图和前端仍在 processing owner 内创建。faer、png 等依赖统一由正式 workspace 管理。
- DBoW2 词典/数据库保留 OpenCV YAML 字段及 `.gz` 压缩；用成熟 YAML/压缩库读取，
  适配 OpenCV 的无空格 flow-map 键分隔和输出缩进约定。词典双向互读已做原 C++ 对照；
  原 FileStorage 的 XML 格式尚未实现。配置文件使用 TOML 的既有选择不影响词典 YAML。

地图位姿、传感器标定及积分测量使用 nalgebra 的 `IsometryMatrix3<f32>` 保存旋转矩阵
和平移；TOML 与 App 深度适配入口直接保留输入矩阵，不经过矩阵与四元数的往返转换。
求和顺序分别对齐本地 Eigen 3.4 的实际表达式：单点 `T*p` 左结合后加平移，
`R*v` 与 `T*Matrix<float,3,8>` 右结合后加平移（纯旋转没有平移项）。逆变换显式
转置旋转矩阵，并按 `(-R^T)*t` 计算平移，覆盖 Map、VolumeCarver 和 Updater。
体素角点、传感器批量角点及 AABB 使用批量路径；更新器的采样增量使用 `R*v` 路径。
`Map::aabb()` 和公共边界变换均有自动对照；世界 AABB 单独覆盖空树及分配一块、两块
后的 18,072 个边界值，属于上表的 78,312 项。

旋转回归保持原 C++ 的三帧输入、深度、地图分辨率和全部查询；y 轴旋转通过矩阵形式的
`Rotation3::from_axis_angle` 构造，对应 C++ 的 `AngleAxis`，不绕经四元数。
一般轴回归直接读取 C++ 夹具中的输入矩阵，隔离矩阵构造公式与后续变换顺序。
迁移时使用 C++ 生成器核验固定夹具；以下为当时的结论。
本次只覆盖矩阵保留和点变换顺序；四元数生成矩阵的公式未改。若调用方传入的矩阵本身
已经包含四元数转换舍入，地图入口保留该输入，不追溯恢复另一套公式的矩阵。
这些结果限于列出的用例，不构成所有姿态或跨平台逐位一致的保证。

**已复现的拒绝路径：** 同为 64×48 深度、0.1 m 分辨率、相机每帧沿 x 平移 0.03 m，
第 0 帧的 99,634 项已定义输出逐值一致；第 1 帧遇到 SE01 窄窗口，Rust 返回错误。
原版使用 `-fsanitize=float-cast-overflow` 时在 `dense_pooling_image_impl.hpp:266`
报告 `-inf is outside the range of representable values of type 'int'`。
该组连续帧验证**没有通过**，没有将错误窗口默认为 level 0 以绕过问题。

具体 OKVIS 深度后端还检查了积分、107 次插值、93 次梯度、150 个缓存三角形、文件输出
和冻结快照。原 SE01 拒绝路径仍单独保留，不因另一帧通过而视为已解决。
