# 原生占据地图管理设计

Firefly 在赛前已经知道墙、台阶和固定设施的位置。机载 planner 用 `firefly-map` 保存固定场地和带测量时间的在线证据。一次局部查询可同时回答这格是否有固定设施、相机最近在这里看到了什么，以及按规划净距是否会碰撞。

## 当前查询与配置

`GridMap::cell_at(point, at, max_age)` 在同一份只读视图中查询 `odom` 坐标。超出规划窗口或坐标无效时返回 `None`。窗口内返回以下三个字段。

| 字段 | 读取方式 |
| --- | --- |
| `fixed_occupied` | 这格是否含有已加载的固定障碍。在线射线可以穿过墙所在的格，固定墙仍会阻挡规划。 |
| `online` | `Free(t)` 和 `Occupied(t)` 保存支持当前分类的深度测量时间。距查询时刻超过 `max_age` 返回 `Expired` 并保留原证据。在线窗口未覆盖返回 `OutsideCoverage`，覆盖内缺少证据返回 `Unknown`。 |
| `collision` | 按规划净距和虚拟地板、顶板判定阻挡。后续射线、概率衰减或占据保留期限都可撤销在线阻挡。查询参数 `max_age` 单独控制此次读取的新鲜度。 |

机载覆盖诊断以当前里程计的测量时间查询，沿用现有 1 秒地图新鲜度期限。空帧、衰减定时器、重复或迟到的深度都不会刷新格子的观测时间。搜索和轨迹复核沿用已有的未知空间通行策略。

已知场地相对本次里程计原点的位姿时，在 planner 配置中添加 `[mapping.field]`，填写场地文件路径和实测的 `odom ← field` 变换。平移单位为米，四元数按 xyzw 排列。相对路径从 Firefly 项目根目录解析。下例使用规划器测试中的地图和位姿。

```toml
[mapping.field]
path = "apps/firefly/planner/tests/fixtures/registered-field.ffmap"
odom_from_field_translation = [-8.0, 0.0, 0.0]
odom_from_field_xyzw = [0.0, 0.0, 0.0, 1.0]
```

默认配置仅加载在线地图。配置场地后，planner 启动时读取场地文件并应用配置的位姿，一次性将固定体素投影到规划网格并计算净距。窗口移走再回来仍可读到固定墙。场地注册在本次 planner 进程内固定。里程计接收器绑定首个有效 IPC 发布端，发布端更换会清空插值历史并锁存停止。重新启动前需确认实测位姿仍对应新的里程计原点。

## 需求出处、消费者与验收边界

启用 `firefly-map` 的 `depth` feature 后，融合写方用 `DepthMapper::new` 绑定相机外参和输出网格，以 `integrate` 提交整帧。返回值区分产生观测、已采纳的空帧和重复或迟到的帧。`snapshot` 同时交付碰撞几何、带时间证据和半开窗口。原始概率数组、膨胀计数和分步回调属于内部实现。[融合入口](https://github.com/3SE-Competitive-Robotics-Team/firefly/blob/main/crates/firefly-map/src/depth.rs) · [快照发布](https://github.com/3SE-Competitive-Robotics-Team/firefly/blob/main/crates/firefly-map/src/depth/snapshot.rs)

四项分别来自比赛场地的固定几何、箱子搬走与转身后的观测、规划器的轨迹复核，以及移窗时的发布耗时。SUPER 和 ANYbotics 的对应源码列在文末，提供了滑窗、增量计数与遍历的实现参考。场地位姿、有效期和性能预算由 Firefly 的输入与验收场景决定。

| 设计项 | 机载路径与实际行为 | 接入边界 |
| --- | --- | --- |
| 场地与坐标 | 配置场地后，planner 按配置路径加载固定层。里程计接收线程把首个有效发布端绑定到测量历史。更换发布端后，深度配对和轨迹交付都失去有效输入。 | 实测 `odom ← field` 属于本次启动。现有 Navigation 携带定位修订，缺少与比赛资产的关联。自动重对齐和运行时换场地需要能提供该关联的输入。 |
| 证据与时间 | 深度线程在 2 Hz 维护时按最新已处理帧的测量时间撤销超龄在线障碍。新射线访问旧障碍时也先重置概率和膨胀。覆盖诊断按当前里程计时间检查自由证据。 | `[mapping.depth].occupied_max_age` 单位为秒，须有限且大于零。省略时沿用正的 `fading_time`，默认 1000 秒。关闭衰减且未指定保留期限时，窗内障碍靠射线清空。自由诊断期限为 1 秒。比赛参数、双阈值和命中与穿过的独立历史需要标注回放支撑。 |
| 查询与版本 | 轨迹接纳、异步求解结果复核、执行中的安全检查均通过 `segment_is_clear` 遍历相邻检查点之间的格。覆盖诊断额外检查净距邻域的自由证据。体素显示用 `visit_occupied` 遍历裁剪区域。`MapInput::synchronize` 统一处理移窗、覆盖与新鲜度检查和安装。 | 线段结果针对采样点间的直线。执行策略允许未知空间。几何修订标识碰撞视图，最后有效观测时间决定可用性，最新已处理帧时间避免提前使用未来窗口。通用区域判定和历史快照选择尚无生产调用方。 |
| 快照与成本 | 膨胀计数跨越零时更新分页位图。生产网格与传感器同分辨率、零原点时，深度线程直接发布环形位图和证据页。旧读者继续读取原页。异网格投影沿用重采样。 | 主机可用下方命令复测移窗。A733 上 VIO 并发时的查询 P95、峰值内存、现场误清率和残留时间需单独采集。 |

以下命令在 release 模式下用默认地图和 320 × 240 合成深度图对比静止与 0.11 m 交替移窗。每组预热 10 帧，再统计 40 帧。

```bash
cargo test --release --locked -p planner repeated_snapshot_timing -- --ignored --nocapture
```

## 比赛里地图必须回答的问题

| 使用场景 | 地图必须提供的功能 | 调用方可以验证的结果 |
| --- | --- | --- |
| 比赛开始，相机还没看到远处的通道 | 读取指定的场地文件，在场地坐标中查询全场固定几何 | 能查出通道两侧的墙。通道中央可报告“底图无固定障碍”，现场是否畅通仍待观测。 |
| 箱子被放在墙边，又被搬走 | 把带时间的命中、射线穿过和未观测分开处理，允许撤销在线占据 | 箱子出现时能定位阻挡来自在线观测。移走后，射线能清除箱子，固定墙始终保留。 |
| 机器人转身或相机断流 | 区分最近确认自由、证据过期、遮挡和超出覆盖，报告最后有效观测时间 | 调用方能分别问“有没有已知障碍”和“整段是否都在最近观察过的自由空间里”。 |
| 局部窗口平移，或定位重新对齐 | 保留重叠区域，跟踪场地版本、里程计会话与对齐关系 | 平移一个格后原地障碍仍在。重定位后不会读到新坐标配旧几何，会话重启也不会沿用原会话的在线障碍。 |
| 多个读者同时查点、查路径、检查一片空间 | 发布一致的只读视图，支持原始格查询与指定净距的线段、区域检查 | 同一次检查始终使用同一版本，两种规划器可以对同一点复现相同结论。 |
| 回放线上问题，或衡量移动时的发布开销 | 使用与线上相同的输入和时钟语义，提供可比较的版本与覆盖信息 | 相同资产与有序输入可复现同一地图。分别计量融合、快照、读取和内存开销。 |

此处的“动态”指现场占据随观测发生变化。上述问题只依赖空间证据、来源和时间，首版可以用体素回答。对象身份、速度和未来位置属于另一个预测需求。

首版假设全场路线只依赖固定几何，现场通行检查只承诺当前局部窗口。离开窗口再回来，原先看到的箱子要重新观测。如果比赛要求绕场一圈后仍记得临时封堵，就需要在全场维护带有效期的在线证据。这个需求会改变在线层的覆盖范围，点、线段和区域查询仍可沿用。

## 两层地图和一个查询视图

| 数据 | 唯一写入者与坐标系 | 保存内容与有效期 |
| --- | --- | --- |
| 场地先验 | CAD 资产流程写文件。地图管理器按配置路径只读加载，坐标系为场地 `map`。 | 复用 `.ffmap` 的米制原点、分辨率、尺寸和未膨胀占据格。装饰体素和仿真障碍航点不写入固定占据。窗口移动、清空在线层和里程计重启均保留该资产。 |
| 在线观测 | 一个融合线程写入当前定位会话的 `odom` 局部网格。 | 保存命中与穿过证据、最近支持当前状态的测量时间。初始和被驱逐的格为未知。箱子等新增障碍和最近确认的自由区域有独立有效期。在线层表示现场观测，也会看到本来就存在的墙。 |
| 查询视图 | 地图管理器从两层及一个已提交的对齐版本生成，读者持有不可变快照。 | 按用途提供场地全图的静态查询、指定 `odom` 窗口的组合查询，以及带净距的碰撞查询。规划器读取视图，行驶或飞行策略由调用者决定。 |

现有比赛文件为 15 cm 网格。离线入口为 `MapFile::to_grid_map`。机载入口按配置建立规划网格，`MapFile::install_fixed` 判断变换后的场地体素与每个规划格是否有体积交叠，占据几何和规划净距各保存一张位图。[CAD 资产契约](https://github.com/3SE-Competitive-Robotics-Team/firefly/blob/78b85df/packages/firefly-cad/README.md)

机载 `apps/firefly/planner` 负责接收深度和里程计、配对位姿、调度定时器，以及记录最后有效帧的到达时间。`firefly-map::depth::DepthMapper` 负责投影、射线更新、衰减和快照打包。planner、搜索和代价计算从同一张 `GridMap` 读取场地与在线几何。回放可直接调用 `DepthMapper::integrate`，传入相同图像、位姿、测量时间和定时器时间。

### 需要保存的数据结构

下表给出拟议的逻辑字段。磁盘继续使用已有场地格式，内存布局可以根据板端测量调整。

| 类型 | 所有者和主要字段 | 对应需求 |
| --- | --- | --- |
| `FieldMap` | 地图库只读持有。包含`map` 原点、格长、尺寸、原始占据位图。 | 查询固定设施。格为空表示该资产未登记固定障碍。 |
| `RayFrame` | 输入适配器构造。包含会话、帧身份、测量时间、`odom` 中的传感器原点及射线。每条射线区分表面命中和已确认的无返回自由区间，无效像素省略。 | 让实机和回放提交相同语义的数据，保留可靠清空边界。 |
| `LocalGrid` 和 `EvidenceCell` | 融合线程独占。网格保存会话、格长、全局格索引的半开窗口与环形偏移。每格保存有界对数几率、最近命中时间、最近穿过时间，未观测时间为空。 | 保存局部占据和自由证据，支持到期、撤销与窗口复用。 |
| `FieldAlignment` | 定位输入提供。绑定场地身份、会话、对齐修订与可信的 `map←odom` 刚体变换。 | 确认底图和当前在线格能够叠加。 |
| `MapSnapshot` | 写方原子发布，读者共享。持有所选层的只读数据、空间范围、最近有效观测及版本。版本区分场地、会话、对齐、几何和证据修订。 | 异步搜索和复核可说明自己读了哪张图，也可复用没有改变的几何。 |
| `CellSample` 和 `SpaceCheck` | 查询临时返回。`CellSample` 分别报告底图状态、在线分类、支持该分类的测量时间及组合分类。`SpaceCheck` 报告整段或整区的结论，以及导致阻挡或证据不足的位置和原因。 | 一个点可以同时有固定和在线两个占据来源。调用者可以解释阻挡、过期或覆盖不足。 |

碰撞膨胀计数和共享块属于派生缓存，由原始占据和净距规则重建。首版只持久化场地先验。在线层随定位会话生灭，事故复查使用同一场地资产与归档观测回放。

当前比赛资产有 201 × 121 × 48 个 15 cm 体素，共 1,167,408 格，内存中的静态占据位图约 143 KiB。全场底图可以直接常驻。以相同原点和轴向按 10 cm 细分覆盖同一范围，则需 3,957,408 格。若每格在线证据按 12 字节估算，仅证据数组约 45.3 MiB，尚需另计膨胀、索引和快照。这个估算给全场在线层与局部窗口提供了可比较的起点，实际峰值由板端测量。[比赛地图文件头](https://github.com/3SE-Competitive-Robotics-Team/firefly/blob/78b85df/apps/firefly/planner/maps/rmuc2027-1.0.0.ffmap#L1-L4)

### 坐标与后续在线场地注册

静态查询直接使用场地 `map`。组合视图使用 `odom`，取同一次提交的 `map←odom` 及其修订号。投影静态层时，将与场地占据格有正体积交集的目标格标为占据，处理旋转、异原点和异分辨率。数字边界采用半开区间，紧邻但不重叠的格保持分离。这样一格厚的斜墙仍有连续覆盖。观测在 `odom` 中独立融合，既有静态墙和新命中重合时，组合视图保留两个来源。

以下事件约定供将来接入在线场地注册时验收。当前部署通过启动时配置登记场地。

| 事件 | 在线注册的目标行为 |
| --- | --- |
| 启动或场地尚未对齐 | 已加载的底图可在 `map` 中查询。本地观测可在 `odom` 中查询。要求组合图的调用返回“等待场地对齐”。 |
| 同一会话提交新对齐 | 保留本地观测，重投影静态层，刷新组合碰撞图。消费者在同一代快照里看到新变换和新几何。旧求解结果须按新视图重验。 |
| 里程计会话重置或坐标连续性丢失 | 撤销旧组合视图，清除在线证据、待配对帧和位姿历史，保留场地文件。新会话建立可信对齐后恢复组合查询。 |
| 更换场地资产 | 在独立缓冲区加载新的场地文件。加载失败时报告错误，继续使用原底图。显式请求新场地的调用保持等待。成功切换后重新确认对齐，原子发布新一代。 |

现有 `NavigationMessage` 提供 `map←odom`、单会话修订号和 `external_map` 标志。比赛接入需要把**场地资产身份、定位会话和针对该场地的可信对齐**明确关联。仅凭修订号、单位变换或 `external_map = 1` 无法确认这一关系。实机场地注册是组合图上线的前置条件。[导航消息](https://github.com/3SE-Competitive-Robotics-Team/firefly/blob/78b85df/crates/firefly-pubsub/src/navigation.rs) · [坐标约定](architecture.md)

## 观测怎样生成和撤销占据

1. 输入适配器交付同一会话、同一测量时刻的传感器原点和有效射线。检查时间、内外参、单位及量程。缺少测量时刻前后位姿的帧进入有界等待。超时帧、重复帧以及测量时间早于已提交观测的迟到帧丢弃。缺失像素和无法解释的返回值保持未知。只有输入明确表示“该范围内已测通畅”时才允许只投自由票。
2. 射线只清除有效测量能支持的可见区间。可信表面端点投命中，遮挡后的格保持原状态。超出局部窗口的有效射线裁剪到边缘，只在窗内累计穿过证据。端点恰在开上界时不投边界命中。同帧同格先合并，命中票达到穿过票数时计一次命中，否则计一次穿过。端点与遍历去重都只在本帧有效。相机回看时，首帧重新确认的自由格立即记录该帧的测量时间。
3. 每格保存概率和支持当前分类的最近测量时间。纯穿过且低于占据阈值时报告自由；进入占据状态后由支持它的命中刷新时间。自由证据超龄后，读取返回原测量时间与过期状态。超龄在线障碍经维护或再次观测撤销。双阈值和分别保留命中、穿过历史的收益由带真值的回放验证。
4. 在融合窗口内按当前 `odom` 的全局格索引寻址，先判边界再计算环形槽位。平移时精确保留新旧窗口的交集，重置离开窗口的槽位及膨胀贡献。无交集时整窗重置。新进入区只继承对应场地先验。原始格分类变化时，局部更新受影响的膨胀计数。两个障碍的膨胀区重叠，移除一个只扣除它自己的贡献。

## 规划器无关的 API

| 现行入口 | 调用方 | 契约 |
| --- | --- | --- |
| `MapFile::install_fixed` | planner 配置加载 | 把已校验资产按实测位姿投影到规划网格，固定几何与净距独立保存。 |
| `DepthMapper::integrate`、`fade` | 深度线程、回放 | 按顺序提交深度和同步位姿。有效帧、空帧和迟到帧各有返回状态。维护定时器推进衰减，以最近已处理的测量时间检查占据保留期限。 |
| `DepthMapper::snapshot`、`GridMap::set_online_snapshot` | 深度线程生成，planner 主线程安装 | 从同一帧取得碰撞、带时间证据和覆盖范围；两个在线层在一次可变借用中安装。异步求解持有安装后的只读副本。 |
| `GridMap::cell_at` | 轨迹覆盖诊断、回放 | 返回固定占据、在线证据及其年龄状态、净距碰撞三项；局部窗口外返回 `None`。 |
| `GridMap::segment_is_clear` | 轨迹复核、安全检查、覆盖诊断 | `KnownObstacles` 检查窗口内线段所经格及其预计算净距。`RecentlyFree` 还要求净距邻域有足够新的自由证据。两端均计入，越界返回 `false`。 |
| `GridMap::visit_occupied` | 体素显示工作线程 | 只遍历与请求区域相交的占据格，区域使用局部整数索引和半开上界。 |

进程内的 `MapInput::synchronize` 是 planner 的适配入口。执行、安全回调及交付都以最新里程计移动窗口，并在同一次调用内检查有效观测的年龄、整窗覆盖和快照时间。状态为 `Ready` 时才安装。过程无需暴露单独的移窗准备步骤。

例如，墙前 20 cm 的箱子搬走后，可靠射线把原箱子所在格更新为自由。原始查询可报告“近期观测自由”，但要求 40 cm 净距的碰撞查询仍报告受墙阻挡。沿窗口边缘做同一查询时，计算净距所需的整个邻域都要有地图覆盖。已知的障碍可以直接判阻挡，其余覆盖不足的位置保留未知。

EGO 适配器沿用现有 40 cm 净距与逐轴立方邻域，保留其虚拟地板、顶板和现行未知通行策略。在线 `CollisionSnapshot` 已含传感器膨胀，`set_online_snapshot` 同时安装这份几何和对应的带时间证据。固定场地在加载时独立计算净距，碰撞查询取两者并集。后续支持在线对齐修订时，求解版本还需纳入定位修订。[求解版本入口](https://github.com/3SE-Competitive-Robotics-Team/firefly/blob/78b85df/apps/firefly/planner/src/main.rs#L475)

### 写入、发布与恢复成本

写线程独占概率、证据时间和膨胀计数。每批融合或到期处理完成后，一次替换不可变快照。测量时间驱动几何配对和回放。单调到达时间检查生产者是否失联。空帧和维护定时器都不能续期“最后有效观测”。证据过期即使没有新帧也要反映在新查询中。

视图的几何版本随占据、净距或覆盖变化。自由证据时间单独更新。同一体素再次被确认通畅，应使自由查询看到新时间，同时保留可复用的碰撞视图。先保留全量生成作为正确性参照，再按全局块索引共享未变化的不可变块，仅替换内容改变的块和滑窗条带。读者一次只取得完整版本，可直接跳过中间版本。用有界在途任务限制同时持有的旧快照数。分块尺寸、年龄存储粒度和到期扫描策略，通过 A733 的内存峰值与移动工况 P95 选定。年龄压缩必须保证旧自由证据不会被相邻格续期。

## 从 ANYbotics grid_map 学窗口与图层管理

ROS 2 Jazzy 的 `grid_map` 在同一张 XY 网格上组织高程、方差等多个属性。每个图层在一个 XY 位置保存一个标量。同一水平位置若同时有地面、可穿过的空间和上方横梁，Firefly 需要按 Z 分别查询占据与观测年龄。因此原始几何继续用三维体素，地面高度等二维视图可在出现具体消费者时派生。[项目说明](https://github.com/ANYbotics/grid_map#overview)

| 上游做法 | Firefly 的设计决定 |
| --- | --- |
| `move(position, newRegions)` 将位移量化到整格，更新环形起点，并列出需要初始化的缓冲区条带。对角移动时各轴条带可以相交。[窗口实现](https://github.com/ANYbotics/grid_map/blob/jazzy/grid_map_core/src/GridMap.cpp) · [移窗测试](https://github.com/ANYbotics/grid_map/blob/jazzy/grid_map_core/test/GridMapTest.cpp) | `LocalGrid` 在一次移窗中保留新旧边界，按全局格坐标计算退出区和进入区。撤销退出格的膨胀贡献后再复用槽位。多轴移动时每个退出格只撤销一次，每个进入格只初始化一次。发布端可用这些区域定位要刷新的块，并计入净距邻域的变化。 |
| 各层共用几何和索引。`isValid(index, layers)` 检查指定层的值是否均为有限数。消息头另带地图时间。[有效性判断](https://github.com/ANYbotics/grid_map/blob/jazzy/grid_map_core/src/GridMap.cpp) · [ROS 2 消息](https://github.com/ANYbotics/grid_map/blob/jazzy/grid_map_msgs/msg/GridMap.msg) | 在线层的概率、最近命中和最近穿过共用同一套三维寻址。静态层保留自己的坐标与分辨率。近期自由查询逐体素检查证据年龄，整张图的发布时间只用于描述快照。 |
| 核心库提供格与区域的遍历，ROS 转换器可选择输出图层，再将所选矩阵写入消息。[遍历接口](https://github.com/ANYbotics/grid_map#iterators) · [ROS 2 转换器](https://github.com/ANYbotics/grid_map/blob/jazzy/grid_map_ros/src/GridMapRosConverter.cpp) | 点查询、线段检查和现有区域遍历沿用同一套全局格索引。进程内规划器持有只读快照，导出由适配器按需执行。移动窗口与发布快照的开销分别测量。 |
