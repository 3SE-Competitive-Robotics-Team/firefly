# 闭环可靠性边界

## 规划器状态输入

`apps/planner/src/state_input.rs` 管理地图系状态的有效性与存活期。
契约对照 [EGO-Planner-v2 状态机](https://github.com/ZJU-FAST-Lab/EGO-Planner-v2/blob/main/swarm-playground/main_ws/src/planner/plan_manage/src/ego_replan_fsm.cpp)
的 `have_odom_` 启动门控与失联后关闭自动恢复；本项目将观测失联的处置定义为停止
发布参考，由飞控负责参考流超时后的模式处理。

- 固定订阅 `Firefly/CorrectedOdometry`，上游必须完成地图对齐，不能自动切换至局部 VIO。
- 首个有效状态到达前不推进任务、不发布参考。启动点仅用于地图加载，执行从实测位置开始。
- 初始化标志、有限数值、单位四元数与严格递增时间戳均需有效。
- 存活期为接收端单调墙钟 500ms，重复和乱序样本不能续期；仿真时间冻结不能掩盖断流。
- 有效流失联或变坏后锁存停止；迟到包与状态恢复不会自动重启任务，需恢复定位并重启进程。
- 规划计算后、发布前再次检查存活期，过期计算结果不得发往飞控。
- 深度投影只用同一来源的历史位姿，位置线性插值、姿态球面插值；不外推、不跨越
  大于 200ms 的采样空洞。每个深度时间戳只消费一次。

域层 `PlannerManager::tick(None)` 保留数学仿真能力；在线应用只在有效观测存在时调用它，
且始终传入实测状态。域层的仿真结果不构成实际飞行状态。

## 仍影响完整闭环的限制

1. **启动范围**：固定停机坪与初始朝向由 `configs/gicp.toml [origin]` 显式提供，
   LightGlue 只在地图系先验邻域查询。该条件支持固定启动，不等价于任意位置全局检索。
2. **飞控降级**：IMU/里程计失效仍会触发应用层零推力，尚无可验收的空中降级控制；
   姿态积分与仿真时间的同步、原始 VIO 原点重置也需要独立运行策略。
3. **感知可用性**：planner 首张深度之前的等待与 GICP 重复深度观测去重仍有缺口。
4. **回环完整性**：已有离线库图匹配、PnP 和融合；在线关键帧、地点检索、回环边
   管理、位姿图优化并未完整实现，不能将当前视觉重定位称为完整回环系统。

飞控反馈固定在 odom 系，地图参考经同时间戳配对得到的坐标树转换；Hold 保持进入
模式时的高度。融合使用统一右误差与协方差换基，数学约束与验收范围见 [坐标契约](frames.md)。

这些限制仍是实际场景验收的前置条件。静态检查和单元测试不能代替 RMUC 实际资产下
的起飞、悬停、遮挡、断流与重定位验证。

## 依赖与验证

Rust/Python 的 iceoryx2 使用同一 0.10 系列；跨语言测试覆盖消息字段、用户头与事件
通知，使用隔离话题，不依赖场景。CI 显式运行这个测试。

- Rust：fmt、Clippy、workspace 测试与 release 规划器随机地图基准。
- Python：MuJoCo、评测指标、CAD 测试。
- `python_interop`：先同步 uv 环境，再用 `FIREFLY_TEST_PYTHON` 指向该环境 Python。
- 依赖选择稳定版本；ORT 采用上游可用的 `2.0.0-rc.13`，Bevy 使用稳定版 0.19.1。
- purecv 固定为 0.7.1；升级必须通过 `lk_displacement_bias` 数值回归测试，不能放宽
  位移误差阈值。该门槛约束 VIO 前端光流的正确性。
- Python 锁文件统一为根 `uv.lock`，构建后端统一使用 uv-build 0.12 系列。
