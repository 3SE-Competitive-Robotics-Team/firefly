# VIO 位移、地图融合与跟踪失效审查

日期：2026-10-03（北京时间）。基线提交 `5d2ad4f`。

## 范围与证据边界

目标为修正已证实的数值错误、降低独立视觉观测延迟、保护先验占据和定位退化时的
控制路径。没有以真值初始化、修正 VIO 或驱动航点切换，没有放宽验收阈值。
真值只用于独立评分和试验场越界/接触终止。越界终止属于仿真试验保护，不是实机能力。

路线按起点的地图水平偏移 `(10,6)`、保持高度解释：
`[-13,0,2.2] → [-3,6,2.2] → [-13,0,2.2]`，不是朝中心障碍直飞。
相对停机坪起飞高度为 1.795m。路线平面净距离约 11.66m。
FFMap 占据中心距离抽样：起点 1.412m、目标 1.924m、直线段最小 0.619m；
这只是几何预检，不代替机器人尺寸膨胀、在线规划或实际碰撞评分。

所有试验复用同一 FFVMAP：
`de4aec777cb6a3bc59a2aa669097ea8ef5320197388d0e5fb7453dc8dbd56180`。
没有重建视觉库、模型或场地。每轮目录保存源码/二进制/配置内容指纹与 RRD。

## 已证实的数学与控制问题

### LK 导数单位与迭代步长

`purecv 0.7.1` 的 LK 使用未归一化 Sobel 导数；单位灰度斜坡的响应为 8。
残差仍使用原灰度单位，因此 `H` 放大 64 倍、右端项放大 8 倍，解出的
Gauss–Newton 步长约为正确值的 1/8。它还会提前满足以像素为单位的终止条件。
独立探针：已知 1px 平移、一级金字塔、一次迭代，原实现只返回 0.12409592px。
这证明了一个数值错误，但不能把单次迭代的比例直接当作整个 VIO 的尺度误差。

LK 使用 fork purecv 的金字塔 LK（OpenCV 语义镜像；上游 issue #163，修复 PR #164）：
图像采样 `REFLECT_101`、导数界外置零、窗口左上角越界检查（最细层判丢，粗层跳过）。
`lk_displacement_bias` 在整数平移 fixture 上的均值误差阈值 2.5px，与 OpenCV 5.0.0
同输入逐点一致（接受集合相同，公共点 rmsd 为零）。

验证不只比较自身代价与梯度：单位斜坡解析导数、中心差分、已知亚像素单步、
正负与大位移量化图像均有独立输出断言。另以理想双目投影、解析 IMU 输入跑完整
传播/三角化/SLAM 更新：10 秒加速运动到 10m，位置和速度误差各小于 0.01m、0.01m/s。
这个试验隔离滤波数学，不能证明真实纹理、遮挡和低频供图下也达到厘米精度。

### 位姿图重复信息与时间间隔

前四邻居边含同一批 VIO 增量，却被当成独立测量；固定边标准差还使融合权重随
关键帧数量改变。解析反例：一秒位移 1m，地图观测 1.1m，两者方差各 0.01m²，
应融合为 1.05m，原实现分两段时得到约 1.04m。

当前使用相邻增量链，`σ_edge = σ_density √Δt`。1/2/4/10 段均检查 1.05m 解析值。
地图与回环仍使用独立绝对/相对约束和 Huber 核。这是扩散近似，没有传播完整 VIO
协方差，也没有宣称地图权重已经统计标定。

同刻原始位姿由首个图节点固定，地图锚点和回环端点复用它；独立 IPC 历史插值
不能覆盖同刻节点。直接 `insert` 内容冲突仍拒绝。测试检查异步端点不改写原始节点。

参考：OpenVINS `6948812`、VINS-Fusion `be55a93`、
EGO-Planner-v2 `9d85475ea7b9bf5c112cf7c3c3d0d3f9e96d9010`、fork `XiaoPengYouCode/purecv`（`main`，含 LK 边界修复）。
VINS-Fusion 的前四邻居连接是其工程选择；引入本项目的绝对地图锚点后，需要独立
检查信息权重，不能凭结构相似认定统计模型正确。

### 占据证据与先验保护

FFMap 先验占据与在线深度共用 log-odds，可能被空闲射线、衰减或动态移除清掉。
当前将先验体素按世界索引固定保存，窗口移回时恢复；在线 free 证据不能清除它。
深度帧按体素统计 hit/miss，多数投票后每帧只更新一次，避免分辨率和重复像素
直接增加观测权重。对照 EGO 的投票公式，未宣称完整复制其射线去重策略。

planner 确实读取 FFMap 和在线深度。问题不等于“planner 没启动”：位置估错时，
它检查的是错误位置附近的地图，深度也会被投影到错误位置。地图膨胀无法补偿任意
大的定位误差。先验保护是独立缺陷；没有证据把基线撞击唯一归因于先验被清除。

### 飞控回退与饱和

- 起飞完成容差只用于模式切换；进入 Hold 后保留指令高度，不锁在提前到达的高度。
- 参考流首次失效即锁存当前 odom 位姿、输出零速度目标；超时仅切换 Hold 模式，
  不能在等待期追向起飞时的旧目标，也不能持续把漂移中的当前位置当新锚点。
- 电机逐个截断负推力会增加总推力。当前分配按总推力、滚转/俯仰、偏航顺序保留
  可行分量，用共同缩放保持差动推力零和。解析测试检查偏航饱和时的总推力、横向
  力矩及总推力导数。这个缺陷独立存在；后续试验表明参考回退旧目标也是爬升的原因。

## 时延与任务质量

图像查询也需要时间配对：用当前地图姿态直接筛选较早图像，在转向时会令正确匹配
被航向门拒绝。当前用 `T_map_body(s) T_odom_body(s)^-1 T_odom_body(t)` 得到图像时刻 t
的查询先验。两个原始 VIO 位姿都需要历史覆盖；解析测试包含 90° 转向、平移和
越界拒绝。这个配对在候选和 PnP 之前完成，后端融合继续按测量时刻配对。

地图查询与在线回环使用独立 ORT 会话，地图算子线程为 2，回环为 1。
回环零容量输入交接、单结果槽，忙时丢帧，不积压旧图像；退出等待线程结束。
候选搜索最多三帧；非平面支撑和 PnP 质量充足时提前返回，否则继续聚合候选。
非平面检查和回退路径有测试。20 个独立库外视角重新验收全部通过（RMSE 0.0516m，最大 0.1213m），结果见
`logs/map_validation_motion_fix.json`，原始事件见同名 RRD；不替代飞行验收。

ALIKED 最小帧间隔为 0.2s，单算子线程，只取最新帧。处理上限不是实际输出率保证。
地图观测仍按图像测量时刻与 VIO 历史配对，随后把校正作用于当前 VIO；
不能将推理完成时刻伪装成测量时刻。

`LocalizationStatus` 独立于地图查询先验：接受的视觉观测年龄超过 3s，或融合后
同刻位置分歧超过 0.5m，禁止跟踪。planner 就绪后退化锁存停止，须显式重启恢复。
这不是误差上界证明，也不是独立于 VIO 的悬停保证。

RRD 实体包括 `vio/debug/camera_age`、滤波状态和偏置、`vision/debug/map_query_wall_s`、
`corr/debug/tracking_quality`、`loop/debug/frontend`、`corr/debug/loops`。
验收进程将子进程 ConsoleReporter 输出转入 `logs/acceptance` TextLog。
日志 IPC 队列容量为 256，进程输出汇集队列 8192；溢出必须显式记录。

## 验证与结论边界

- `cargo test --workspace` 通过；包括解析 VIO、LK、图优化、先验保护和飞控契约。
- `cargo test -p firefly-planner --test planner_contracts`：33 项通过。
- 独立视觉库查询 20/20 通过；几何资产和模型保持不变。
- Python `tests/evaluation`：29 项通过。
- Rust/Python IPC payload、header 与事件往返契约通过。
- 完整往返必须同时通过悬停、轨迹、定位、碰撞和退出评分；上述调试轮次没有一轮
  全部通过。数学单元测试通过与地图 RMSE 降低都不能代替这条结论。

剩余重点：降低独立视觉有效观测间隔的长尾，量化真实图像前端剩余位移偏差，
检查机动时飞控姿态与推力控制的跟踪误差，并用同版本往返任务复验。
